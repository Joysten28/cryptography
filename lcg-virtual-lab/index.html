2. Theoretical Background

Mathematical foundation, recurrence formula, and security analysis

General Recurrence Formula
X_{n+1} = (a \cdot X_n + c) \pmod m

where $X_{n+1}$ is the next pseudorandom integer, given current state $X_n$.

X₀

Seed Value (X₀)

Initial integer state of the generator. Must satisfy $0 \le X_0 < m$.

a

Multiplier (a)

Constant factor scaling previous state. Must satisfy $0 < a < m$.

c

Increment (c)

Constant offset added per step. Must satisfy $0 \le c < m$. If $c=0$, it is a Multiplicative Congruential Generator (MCG).

m

Modulus (m)

Upper bound modulus determining state space size. Must satisfy $m > 0$. Maximum possible period length is $m$.

N

Iterations (N)

Total number of sequence elements to generate in the simulation step.

Uₙ

Normalized Output (Uₙ)

Floating-point value in $[0, 1)$ computed as $U_{n+1} = X_{n+1} / m$.

Hull-Dobell Theorem (Max Period Conditions)

An LCG achieves a maximum period length equal to $m$ for all seed values $X_0$ if and only if:

  • 1. $c$ and $m$ are relatively prime (i.e., $\gcd(c, m) = 1$).
  • 2. $a - 1$ is divisible by every prime factor of $m$.
  • 3. $a - 1$ is divisible by $4$ if $m$ is divisible by $4$.

Cryptographic Vulnerability Notice

LCG IS NOT CRYPTOGRAPHICALLY SECURE!

LCGs are completely linear and deterministic. Given a few consecutive outputs (or even normalized floats), an attacker can easily solve a system of linear congruences to recover the hidden parameters ($a, c, m$) and predict all future and past outputs in $O(1)$ time using basic modular arithmetic.

9. Advantages & Cryptographic Limitations

Evaluating LCG efficiency against cryptographic attack surfaces

Advantages & Ideal Use Cases

  • Extremely Fast: Requires only one multiplication, one addition, and one modulo operation per number.
  • Minimal State Memory: Requires storing only a single integer state variable ($X_n$).
  • Reproducibility: Given the same seed $X_0$, the exact same sequence is generated reproducibly.
  • Non-Critical Applications: Excellent for Monte Carlo simulations, simple video game RNG, procedural generation, and graphics.

Cryptographic Flaws & Failures

  • Full Predictability: Knowing 3-4 consecutive outputs exposes $a, c, m$, allowing full state recovery in $O(1)$ time.
  • Marsaglia's Lattice Theorem: Sequence points plotted in $k$-dimensional space fall on a small number of parallel hyperplanes ("RNGs fall mainly in the planes").
  • Low-Order Bit Periodicity: When $m$ is a power of 2 ($2^k$), the lowest $b$ bits have a period of only $2^b$. The last bit alternates between 0 and 1!
  • RANDU Disaster: Historical LCG with $a=65539, m=2^{31}$ caused catastrophic failures in 1960s 3D scientific simulations.

10. Conclusion & Recommendations

Summary of findings and modern secure alternatives

The Linear Congruential Generator (LCG) is a fundamental, elegant, and computationally lightweight algorithm for pseudorandom number generation. However, due to its linear recurrence structure $X_{n+1} = (a \cdot X_n + c) \pmod m$, it exhibits severe structural predictability and dimensional hyperplane lattice alignment.

Cryptographic Recommendation

For secure applications (key generation, session tokens, encryption IVs, digital signatures), NEVER use LCG. Instead, use Cryptographically Secure Pseudorandom Number Generators (CSPRNGs) such as:

Web Crypto API (crypto.getRandomValues()) AES-CTR DRBG ChaCha20 PRNG HMAC-DRBG (NIST SP 800-90A)
